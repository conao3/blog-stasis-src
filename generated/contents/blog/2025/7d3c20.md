作者のREADMEを見るのが定石ですが、ClojureはREPL文化のため処理系と対話しながらインターフェースを調査しながら動かすことも可能です。
ここでは clojure.data.csv を使いたくなったとします。


# 依存解決

まずは依存解決する必要があります。
ここで重要なのは使いたいライブラリが **mavenで** どういう名前なのかです。
実際のところ、これを調べるためにはGitHubのREADMEを見るしかありません。
clojure.data.csv の場合、 [clojure/data.csv](https://github.com/clojure/data.csv) が公式のGitHubです。

これを見ると deps.edn の表記が以下であることが分かります。

```clojure
org.clojure/data.csv {:mvn/version "1.1.0"}
```

しかし、ここでREADME上のバージョン情報が更新されているとは限りません。
mavenを見に行くと [org.clojure/data.csv](https://mvnrepository.com/artifact/org.clojure/data.csv) を見つけることができ、ここで最新のバージョンが `1.1.0` であることが確かめられました。

`deps.edn` 表記はそのまま `clojure.repl.deps/add-lib` に渡すことができます。

```clojure
user> (add-lib 'org.clojure/data.csv {:mvn/version "1.1.0"})
```

これで依存解決は完了です。


# requireしてみる

名前空間の調査に入りますが、ここでも問題があります。
Clojureに対してどういう名前で公開されているかを調べる必要があります。
公式のREADMEを見ると以下の表記があるため、 `clojure.data.csv` が名前空間であることが分かります。

```clojure
(require '[clojure.data.csv :as csv]
         '[clojure.java.io :as io])
```

`require` した名前空間は `:as` を使って別名を付けることができます。
雰囲気で付けてください (えっ

大まかに分けてそのままにするか、ある程度のレベルだけ省略するとするか、最後だけ採用するか、1文字にするかくらいの選択肢があります。

-   clojure.data.csv
-   data.csv
-   csv
-   c

ここで付ける命名は名前空間での名前のため、変数名とは衝突しません。


# 公開関数を調べる

公開 **関数** というのは正確には誤りで、実際には **Var** という単位で取得できます。
それを取得するには `clojure.core/ns-publics` という関数を利用します。

```clojure
user> (ns-publics 'clojure.data.csv)
{read-csv #'clojure.data.csv/read-csv,
 Read-CSV-From #'clojure.data.csv/Read-CSV-From,
 read-csv-from #'clojure.data.csv/read-csv-from,
 write-csv #'clojure.data.csv/write-csv}
```

このように `ns-publics` はシンボルとVarのマップを取得することができます。

この構造が得ることができれば以下のようにVarを分類できます。

```clojure
(-> (->> (ns-publics 'clojure.data.csv)
         (map (fn [[key val]]
                [key (cond
                       (fn? (var-get val)) :fn
                       :else :else)]))
         (group-by second))
    (update-vals (partial map first)))
;;=> {:fn (read-csv read-csv-from write-csv),
;;    :else (Read-CSV-From)}
```
