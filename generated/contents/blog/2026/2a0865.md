Title: e-Govの法令8,986件を90秒で検査して、条文を読んで確かめた食い違いを44法令で出すritsulintを作った
Date: 2026-11-17 16:37
Tags: rust lean japanese-law linter formal-verification release rust-ritsulint lean-leanfran


日本の法令を検査するlinterのritsulintを作りました。
[e-Gov法令検索](https://laws.e-gov.go.jp/)が配っている法令XMLを読み、条文どうしが食い違っている箇所を警告として出します。

法令は、ほかの規定を位置と文言の引用で指します。
改正は条文の一部だけを書き換えるので、引用された側だけが変わると、引用が条文のどこにもない状態になります。
e-Govが収録する憲法、法律、政令、勅令、府省令、規則は、2026-11-17の時点で8,986件です。
その本則をすべて読んで13種類の検査にかけるのに、Core i5-8400の1スレッドで約90秒かかります。
引用が引用先の条文のどこにもない読替え規定が30法令で見つかりました。
指す先の項がない「前条第二項」のような参照も14法令にあります。
この44法令は警告を条文と照らして読み、食い違いを確かめたものです。

警告の一覧は[ritsulint.conao3.com](https://ritsulint.conao3.com/)で公開しています。
リポジトリは[conao3/rust-ritsulint](https://github.com/conao3/rust-ritsulint)で、ライセンスはApache-2.0です。

# 読替えの引用が条文にない

法令には「第○条中「A」とあるのは「B」と読み替える」という読替え規定があります。
別の場面に同じ条文を使い回すための書き方です。
Aは引用先の条文の文言をそのまま写したものです。

出入国管理及び難民認定法の第13条第7項は、第41条第1項を仮上陸の場面に準用するために、次の文言を引用しています。

> 三十日以内とする。但し、主任審査官は、やむを得ない事由があると認めるときは、三十日を限り延長することができる。

現行の第41条第1項は「ただし」と平仮名で書かれていて、「但し」はありません。
ritsulintはこの食い違いを次のように出します。

![img](../../../../resources/public/img/2a0865-warning.png)

各法令の過去のバージョンをすべて検査すると、警告がどのバージョンから出ているかが分かります。
この警告は2024-06-10施行のバージョンから出ています。
令和5年法律第56号が第41条を書き換え、第13条の引用はそのまま残りました。
同じように、バージョンの履歴から、引用先だけが変わって生じたと決まる警告が30件あります。


# 「前条」が指す条が変わる

法令は「前条第二項」「次項」「前三号」のように、相対的な位置でも規定を指します。
間に条を足す改正があると、同じ言葉が別の条を指すようになります。

鉄道事業法施行規則の第46条は「前条第二項第一号の索道施設の設置の場所を示す図面」と書いています。
図面を定めているのは第45条第2項です。
2019-09-14施行の改正で第45条の2が間に入り、「前条」は1項しかない第45条の2を指すようになりました。

プログラムなら、関数を1つ足しただけで呼び出しの相手が変わることはありません。
法令は規定を名前でなく位置で指すので、条を足す改正がそのまま参照を壊します。

警告は確度で3段に分けています。
条文を読んで確かめたものと、番号や目次のように条文の構造だけで決まるものが「高」で、139件あります。
残りは誤検出を含みます。
とくに表の最後の行の2つは、別の語や一般の語を拾うことが多く、全件を「低」にしています。

条番号を直接書いた参照の指す先があるかは、検査に入れていません。
「第十条第二項」が自分の法令の条なのか、少し前に名前の出た別の法令の条なのかを、機械で決められなかったからです。
どの法令の位置かも文脈で決まるところが、プログラムの名前解決と違います。


# 使い方

Nixがあれば、法令XMLを1つ渡して検査できます。

```shell
nix run github:conao3/rust-ritsulint -- law check-law \
  --xml-file 326CO0000000319_20240610_505AC0000000056.xml \
  | jq '.Warnings[] | select(.Rule == "read-as-quote") | {Id, Status, Source, Targets, Confidence}'
```

出入国管理及び難民認定法の2024-06-10施行のバージョンでは、読替えの引用の警告が1件出ます。

```json
{
  "Id": "bd316ca07e22167f",
  "Status": "absent",
  "Source": {
    "Article": "13",
    "Paragraph": 7
  },
  "Targets": [
    {
      "Article": "41",
      "Paragraph": 1
    }
  ],
  "Confidence": "high"
}
```

`Id` は法令、検査、条・項、引用した文言から計算し、バージョンを含めません。
2つのバージョンの出力をIDで突き合わせると、その間の改正で増えた警告が分かります。
1つ前の2024-04-01施行のバージョンでは、この警告は出ません。

全法令をまとめて検査するときは、e-Govの[一括ダウンロード](https://laws.e-gov.go.jp/bulkdownload/)を展開したディレクトリと基準日を渡します。
8,986件を読んで検査するのに約90秒かかります。

```shell
nix run github:conao3/rust-ritsulint -- corpus check-corpus \
  --xml-dir path/to/xml --as-of 20261117
```


# 条文の読み方をLeanで書く

漢数字、読替え規定の分解、「同条」「前項」の解決のような条文の読み方は、Lean 4で書いています。
実際の条文に対する出力は `decide` で検査し、Leanのカーネルが確かめます。
読替え規定の「AとあるのはBと」の1組を、この記事では句と呼びます。
入管法の第13条第7項なら、4つの読替えの句がそれぞれ第40条、第40条、第41条第1項、第41条第3項と第42条第1項を指すことを確かめています。
Leanのコードは[leanfran](https://s.conao3.com/blog/2026/23d62c)でRustに変換し、XMLの読み込みと照合をするRustから呼びます。

解決できない書き方には警告を出しません。
読替えの句59,659件のうち、同じ法令の条・項に解決して照合したのは21,848件です。
別の法令の条を指す句は、法令名か法令番号で法令を特定できた1,233件だけを照合しています。


# 読替えの意味を定義して定理にする

読替え規定は、1つの項に句をいくつも並べます。
公職選挙法の第34条の2を例にします。
第3項は、地方公共団体の長の選挙の告示の前に議会の議員がすべていなくなった場合に、長の選挙を行う時期を定めています。
次の文は第3項の前半で、後半には長と議会の議員を入れ替えた同じ形の文が続きます。

> 第三十三条第一項及び第一項の規定にかかわらず、前項の規定による告示がなされた後当該地方公共団体の長の任期満了による選挙の期日の告示がなされるまでに当該地方公共団体の議会の議員が任期満了以外の事由によりすべてなくなつた場合（当該地方公共団体の議会の議員の任期満了による一般選挙の期日の告示がなされている場合（第三十三条第四項ただし書の規定の適用がある場合を除く。）を除く。）における当該地方公共団体の長の任期満了による選挙は、当該地方公共団体の長の任期満了の日前五十日に当たる日又は当該地方公共団体の議会の議員の任期が満了することとされていた日前三十日に当たる日のいずれか遅い日から当該地方公共団体の長の任期満了の日までの間に行い、

第4項は、長と議会の議員の立場が逆の場合に、この第3項を読み替えて使います。
第3項についての読替えは次の部分で、句が10個あります。
3番目の句は「長の任期満了による選挙」を「議会の議員の任期満了による一般選挙」に読み替え、5番目の句はその逆に読み替えています。

> 前項中「第一項の」とあるのは「次項において準用する第一項の」と、「前項」とあるのは「次項において準用する前項」と、「長の任期満了による選挙」とあるのは「議会の議員の任期満了による一般選挙」と、「議会の議員が任期満了以外の事由によりすべてなくなつた」とあるのは「長が任期満了以外の事由により欠け、又は退職を申し出た」と、「議会の議員の任期満了による一般選挙」とあるのは「長の任期満了による選挙」と、「長の任期満了の日」とあるのは「議会の議員の任期満了の日」と、「議会の議員の任期が満了することとされていた日」とあるのは「長の任期が満了することとされていた日」と、「長が欠け、又は退職を申し出た」とあるのは「議会の議員がすべてなくなつた」と、「議会の議員の任期満了の日」とあるのは「長の任期満了の日」と、「長の任期が満了することとされていた日」とあるのは「議会の議員の任期が満了することとされていた日」と読み替えるものとする。

元の第3項に10個の句を同時に当て、句が書いた文言は読み直さずに読むと、前半は次の文になります。

> 第三十三条第一項及び次項において準用する第一項の規定にかかわらず、次項において準用する前項の規定による告示がなされた後当該地方公共団体の議会の議員の任期満了による一般選挙の期日の告示がなされるまでに当該地方公共団体の長が任期満了以外の事由により欠け、又は退職を申し出た場合（当該地方公共団体の長の任期満了による選挙の期日の告示がなされている場合（第三十三条第四項ただし書の規定の適用がある場合を除く。）を除く。）における当該地方公共団体の議会の議員の任期満了による一般選挙は、当該地方公共団体の議会の議員の任期満了の日前五十日に当たる日又は当該地方公共団体の長の任期が満了することとされていた日前三十日に当たる日のいずれか遅い日から当該地方公共団体の議会の議員の任期満了の日までの間に行い、

長と議会の議員が入れ替わり、議員の選挙の告示の前に長が欠けた場合の文になりました。
句を書かれた順に1つずつ条文の全体にかけると、同じ前半が次の文になります。

> 第三十三条第一項及び次項において準用する第一項の規定にかかわらず、次項において準用する前項の規定による告示がなされた後当該地方公共団体の長の任期満了による選挙の期日の告示がなされるまでに当該地方公共団体の長が任期満了以外の事由により欠け、又は退職を申し出た場合（当該地方公共団体の長の任期満了による選挙の期日の告示がなされている場合（第三十三条第四項ただし書の規定の適用がある場合を除く。）を除く。）における当該地方公共団体の長の任期満了による選挙は、当該地方公共団体の長の任期満了の日前五十日に当たる日又は当該地方公共団体の議会の議員の任期が満了することとされていた日前三十日に当たる日のいずれか遅い日から当該地方公共団体の長の任期満了の日までの間に行い、

3番目の句が書いた「議会の議員の任期満了による一般選挙」を、5番目の句が「長の任期満了による選挙」に戻しています。
長が欠けた場合に長の任期満了による選挙を行う文になり、意味が通りません。
この項が意図している文は、すべての句を元の第3項に同時に当てたときにだけ得られます。

そこで読替えの意味をLeanで定義しました。
条文を左から1回だけ読み、句が引用する文言のある場所に、その句の読替え後の文言を書きます。
同じ場所に複数の句の引用があれば、長いほうを取ります。
句が書いた文言は読み直しません。
ritsulintはこの定義をRustに変換して実行しています。

句を1つずつ置き換えた文がこの定義の文と同じになる条件もLeanで定義しました。
条件は2つで、どの句の引用も前の句の引用と重ならないことと、前の句が書いた文言の中に現れないことです。
次の定理では、すべての句とすべての条文について、条件を満たす句なら2つの読み方が同じ文になることを証明しています。

```lean
theorem applySeq_eq_applyAll (cs : List (Clause α)) (t : List α)
    (h : independent cs t = true) : applySeq cs t = applyAll cs t
```

e-Govの法令には、1つの項が同じ条・項に2つ以上の句をかけている箇所が4,854あります。
このうち条件を満たし、1つずつ置き換えても同じ文になる箇所は4,602です。
句を1つずつ置き換えると文が変わる箇所は219あり、公職選挙法の第34条の2はここに入ります。
条件を満たすのに文が変わる箇所は0でした。

読み方が1つに決まらない箇所もあります。
特定農林水産物等の名称の保護に関する法律の第30条は、第3条第2項の「変更の登録」を「指定の変更」に、「登録の日」を「指定の日」に読み替えます。
条文にあるのは「変更の登録の日」で、2つの引用が「登録」で重なっています。
左から読むと「指定の変更の日」、右から読むと「変更の指定の日」です。
読む向きで文が変わる箇所は12あり、警告として出しています。

定義の関数を小さく壊したときに定理が成り立たなくなるかは、[lean-leanassay](https://github.com/conao3/lean-leanassay)で検査しています。
壊したバージョンを54個作り、そのすべてで定理が成り立たなくなることを確かめます。
条件の検査を1つ外したバージョンは、入れ替えの句で2つの読み方が食い違います。

XMLから条文を取り出す処理や項を句に分ける処理、LeanからRustへの変換は証明していません。
引用が条文にあるかの照合もRustの文字列の比較で、証明の外にあります。
左から読んで長い引用を取る読み方は、私が定義として選んだものです。

確度が「高」の読替えの警告のうち35件には、引用先の条文に読替えを適用しても文が変わらないことをLeanのカーネルが計算した記録を付けました。
この記録は1件ごとの検算なので、定理と分けて証明書と呼んでいます。
定義と証明は[ReadAs.lean](https://github.com/conao3/rust-ritsulint/blob/master/lean/Ritsulint/ReadAs.lean)に、証明書は[Findings.lean](https://github.com/conao3/rust-ritsulint/blob/master/lean/Ritsulint/Findings.lean)にあります。


# 警告が言えること

警告が示すのは、e-Govのデータの上での食い違いです。
官報に載った法令そのものの誤りかどうかは、改正法令の原文と照らすと決まります。
入管法、電波法施行規則、介護保険法施行令など7法令は、改正法令の原文でも引用が直されていないことを確かめました。
満載喫水線規則の警告は英数字の全角と半角の違いで、データ化で生じた食い違いと考えられます。

読替えの引用が条文と1字違っていても、どの規定を指しているかは人が読めば分かります。
それでも、引用が条文にあるかは機械で確かめられ、e-Govの法令すべてでも90秒で終わります。

改正案を作る段階で同じ検査にかければ、取り残された引用は公布の前に見つかります。
